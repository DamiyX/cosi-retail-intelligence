dataset root, manifest inside it, relative ASCII forward-slash asset locators,
SHA256 of exact bytes, identity/package/known relations, duplicate hashes and
capture-session leakage. No URLs, drive paths, traversal, escaping symlinks or

specified files and manifest assets; it never discovers images recursively.

This command requires exactly manifest, dataset-root, curation and out. It writes
`readiness.json` and `readiness.md` to the supplied output, which must be inside
ignored `apps/recognition-lab/runs/`. Both destinations and every ancestor are
preflighted before any directory creation/write. Linked/dangling/hardlinked or
non-file outputs and source/output aliases reject, including Windows8.3 aliases
checked by exact bigint file identities. Manifest, every declared asset and the
curation sidecar are protected even when invalid/missing. Missing paths bind to
their nearest existing physical ancestor; error reports cannot create/replace
an input. Both report targets must be physically distinct. Fresh nested output
and safe regular-file rewrites remain supported. Sequential local use only;
hostile filesystem races and atomic multi-report writes are not claimed.
For readiness only: exit0 means all recorded preparation checks passed and the
dataset is eligible for independent curator acceptance; exit2 is valid but
incomplete; exit1 is invalid input/arguments/I/O. No real exit0 dataset exists in
this repository. Dataset/sidecar invalidity writes sanitized INVALID reports
after output/input preflight passes. Preflight rejection exits1 without creating
directories or changing any reports/inputs; argument/output-I/O failures may
leave old output, so always check the exit.
Existing run/validate/sweep semantics are unchanged.

Five separate states report integrity validity, curator review completeness,
capture coverage, holdout seal and real-dataset readiness. Counts show enrolled,
declared and represented products; distinct captured packages and packaging
generations; references and known/unknown queries with exact ratios by split;
reference views and declared query families per product; missing package truth;
query challenge/lighting/view/occlusion gaps; known unseen-package and disclosed
manual-choice challenges. Coverage policy `r1-capture-coverage-v1` is preparation
guidance, not an accuracy threshold or statistical sufficiency claim.

Missing decisions/bindings/reviews/seal generate incomplete reports. Incorrect
non-null bindings, malformed/unknown fields, duplicate/orphan reviews, stale asset
hashes, rights-reference contradictions, family leakage/conflicts or stale/inexact
seal inventory are invalid. An invalid sidecar leaves capture states NOT_ASSESSED;
no partial coverage is called valid. Every rejected manifest entry remains counted.
Reports contain pseudonymous IDs/hashes/counts, no asset bytes or private absolute
paths; the curator must ensure IDs themselves contain no private information.

Synthetic datasets, synthetic curator evidence and authored observations cannot
satisfy real-dataset readiness. Real-capture manifests may omit observations and
can be assessed without selecting/executing an encoder. The template's unselected
adapter fields are placeholders. A later R2 packet owns real encoder metadata and
execution; no R1 asset-resolution or thumbnail policy selects preprocessing.

Versioned template details: `templates/r1-v1/README.md`. Checked-in
`fixtures/r1-curation.json` binds the R0 text manifest but intentionally has no
reviews/seal. Use it only to inspect missing evidence. R0 vectors remain authored.
