## Run public authored examples

From the repository root in PowerShell, use the pinned toolchain:

```powershell
$env:PATH = 'C:\Users\doyew\.cache\cosi-toolchain\node-v24.21.0-win-x64;' + $env:PATH
node apps/recognition-lab/src/deviceBenchmarkCli.ts analyze --manifest apps/recognition-lab/fixtures/dataset.json --dataset-root apps/recognition-lab/fixtures --candidate apps/recognition-lab/fixtures/r2/toy-a.json --target apps/recognition-lab/fixtures/r3/target.json --record apps/recognition-lab/fixtures/r3/paired-benchmark.json --reference-bundle apps/recognition-lab/fixtures/r2/toy-a-development.json --pairs apps/recognition-lab/fixtures/r3/paired-equivalence.json --out apps/recognition-lab/runs/r3-example
```

Exit **0** means this supplied record has the modeled coverage and recorded pairs
within its declared experiment tolerances. It establishes **no native pass**.
Replace `paired-equivalence.json` with `drift.json`: exit **2**, one recorded drift.
Use `benchmark.json` and `equivalence.json`: exit **2**, reference failure retained
in the nine-pair denominator. Omit both optional pair arguments: exit **2**, missing
equivalence analysis. Use `incomplete.json` without pairs: exit **2**, null
observations and missing trial/measurement coverage. Use `failure.json` without
pairs: exit **2**, 111 attempts, 110 successes and one untimed timeout.

Exit **1** means invalid arguments/input/binding/I/O/output confinement. For
example, an output under `fixtures/` is rejected. Reports are written only under
ignored `apps/recognition-lab/runs/`. Before creating directories or writing any
report, the complete JSON/Markdown destination set is checked: reject linked or
non-directory ancestors, symlinks/junctions (including dangling links), hardlinked
files and non-file destinations. Protect the manifest, every manifest asset,
candidate, target, record and any supplied reference/pair file from output
collisions. Canonical paths and exact bigint device/inode identity both matter:
Windows realpath can retain8.3 spelling, so path strings alone cannot protect a
long-path input reached through a short output-directory alias.

Existing safe regular reports may be rewritten; no source input may be replaced.
Preflight rejection leaves all report siblings/inputs untouched and creates no
directories. Errors expose a code, never source paths, raw vectors or stack
traces. This guard assumes sequential local filesystem use; it is not an atomic
multi-report transaction or protection against hostile concurrent path replacement
after preflight. Keep other processes from changing output paths while writing.

`device-benchmark.json` and `.md` are deterministic for identical supplied files
and Node version; this command has no measured runtime/timing field. File hashes
bind inputs. Canonical candidate/target/bundle hashes bind parsed declarations as
specified by R2/R3 modules. No directory discovery, network, image decoding,
encoder execution or child process/Git command is performed by this CLI. Dataset
import reads exactly the manifest assets inside the explicitly supplied root.
No report includes asset locators, vectors, candidate free-text descriptions or
private paths. Only safe IDs refer to separately held human evidence.

## Capture record contract

Start later with `templates/r3-v1/benchmark.json`. It is intentionally empty and
invalid until exact bindings are supplied; its nulls are not observations.
Public examples are generated by `fixtures/r3/generate.mjs`; it authors numeric
values and identities and does not measure anything. Its export hash differs
from original weights by design. Never relabel these fixtures as physical data.

For each candidate/export/runtime/device/condition record:

- Supply the validated R2 candidate declaration, its canonical hash, original
  artifact hash, preprocessing ID/version/hash and embedding space/dimension.
  Draft candidates are rejected. Review references are declarations requiring
  independent human review, not cryptographic proof of rights or execution.
- Supply a separate target declaration: exact exported artifact hash, format,
  precision, conversion-method ID and review reference; runtime ID/version,
  binary hash, delegate, configuration hash and review reference. Original
  weights and converted export hashes are different identities and need not
  match. A different target requires a different binding/record.
- Bind dataset ID/version/kind/exact manifest-file hash and every inventoried
  entry/asset hash. Inventory is explicitly supplied; the tool does not claim
  every real attempt was collected. Record a device pseudonym, public-safe model
  and Android-version IDs, and an ID for conditions/evidence stored separately.
- Use `authored-toy` only with authored candidates/synthetic datasets. Physical
  records use `reported-physical-unverified`, real-capture manifests without
  authored observations, reviewed-real R2 declarations and a recorded timestamp.
  Even full supplied coverage leaves native acceptance pending.
- Trials require unique IDs, stage, phase (`cold`, `warmup`, `warm`), method and
  evidence IDs. Inference/result trials require exact inventoried entry/hash;
  startup/camera-ready may have null input. Successful elapsed milliseconds must
  be finite/nonnegative; failures explicitly use ADAPTER_ERROR, TIMEOUT, CRASH or
  UNAVAILABLE, with elapsed milliseconds or null. Do not replace a failure with
  an UNKNOWN recognition result or drop it.
- Memory/storage/sustained/thermal/battery/stability/offline observations are
  null or `{value, methodId, evidenceId}`. Bytes are safe nonnegative integers;
  methods reference actual measurement instruments and separately held notes.
  Zero is only an explicitly supplied measured/authored value, never missing.
  Optional extrapolations are separate from actual storage and not required.

The summary emits every stage/phase group without pooling device, runtime, stage
or phase. It shows all attempts, successes, failures and warmups. Successful-only
latency is explicitly labeled supplied/unverified, alongside failures. Median
uses ordered middle values; nearest-rank p90 requires at least 10 successes and
p95 at least 20. Smaller tails are null. These sample cutoffs support descriptive
reporting, not rare-error reliability. Missing observations and stages are listed;
false supplied offline checks and observed instability/throttling are concerns.
Ten-minute supplied duration is a coverage check, never automatic thermal safety.

## Paired recorded numerical equivalence

Supply both `--reference-bundle` (accepted R2 bundle format) and `--pairs`.
The pair record binds the same candidate/dataset/preprocessing/space/dimension,
benchmark-record ID, target-declaration hash, selected split and canonical reference
bundle hash. Its experiment must explicitly name finite nonnegative
`maxNormalizedError` and `maxCosineDifference` tolerances and an experiment ID.
Use tolerances justified for the exact real export/precision experiment later;
the toy 0.000001 values are authored examples, not recommendations.

Every benchmark inventoried input needs a native recorded output and an exact
same-input reference in the supplied R2 bundle. Duplicate, missing, orphan, stale,
wrong-space, wrong-dimension, zero and nonfinite vectors are rejected. Explicit
failures on either side are retained; successful intersection is never the
inventory. R2's complete bundle checks still apply to the reference, even when
this experiment uses a smaller explicit benchmark subset.

Central `unitVector` normalization is reused. Coordinate maximum absolute error
is measured on normalized vectors; cosine difference is `1 - clamped(dot)`.
Bounds are inclusive. Pair counts show inventoried, compared, within tolerance,
drift, failed, reference failures and native failures (the last two can overlap).
All-failed maxima are null. Reports contain scalar errors/failure codes and safe
input IDs/hashes, never vectors. Agreement proves only recorded numerical
agreement. Actual export correctness, inference execution, ranking changes and
near-threshold recognition behavior require separate real evidence.
