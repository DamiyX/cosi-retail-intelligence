## Bounded candidate direction, not adoption

Two initial family hypotheses: small mobile visual embedding baseline and mobile
image-text encoder. Google's [image-embedder guide](https://developers.google.com/edge/mediapipe/solutions/vision/image_embedder)
describes MobileNetV3 small/large embeddings, resizing/color normalization and L2
options. Its Pixel6 latency is not Galaxy evidence; page/code licences do not
establish weight redistribution rights. MobileNetV3 small is a candidate family
only; exact artifact/revision/weight terms/hash remain unreviewed.

Apple's [official MobileCLIP repository](https://github.com/apple-aiml-research/ml-mobileclip)
and [model terms](https://github.com/apple-aiml-research/ml-mobileclip/blob/main/LICENSE_MODELS)
separate code and model terms. A mobile image-text MobileCLIP family is a
comparison hypothesis, not commercial acceptance or verified SKU discrimination.
Neither candidate is downloaded, selected or assigned an invented checksum.
Bounded primary-source review October2 supports a small comparison; no broad
model search, final runtime or licence inference is needed for preparation.

## Artifact contracts and failure handling

Keep contracts lab-local. Candidate declarations distinguish draft/unreviewed from
executable evidence. Exact identity includes candidate/version, artifact SHA256,
preprocessing descriptor/version/hash, embedding space/dimension, code/weight
licence review references and status, export/runtime provenance/status and storage
bytes when actually measured. Do not treat null or placeholder identifiers as
reviewed. Authored synthetic candidates are explicitly toy-only, never disguised
as real MobileNet/MobileCLIP weights. Real eligibility requires reviewed exact
artifacts and provenance; do not let a Boolean create real acceptance automatically.

Embedding result bundle binds to exact dataset manifest hash/version/kind and
candidate/preprocessing identities. One output per required reference and selected
query entry, bound to asset SHA256. Reject duplicate/orphan/missing bindings,
wrong dimensions/nonfinite/zero vectors, wrong version/space or cross-candidate
mixing. Explicit per-query encoder failures remain counted; do not replace them
with UNKNOWN or silently drop them. Failed reference encoding prevents gallery
setup and yields an explicit failed-candidate/setup result. It does not shrink
the gallery invisibly or fabricate zero-query accuracy. No asset scanning, remote
URL fetch, arbitrary process execution or private binary/image report export.

Use existing ranking/normalization/metrics at an isolated adapter seam. Evaluate
each candidate separately in its own vector space; compare rates, not distances
across spaces. Comparisons use identical manifest, split and query population;
per-candidate preprocessing may differ but must be explicitly pinned. Failure
records keep cardinality. Exact reports include dataset/artifact/config hashes,
kind, provenance and missing real evidence. Precomputed timestamps/durations are
reported provenance or unverified reported timing, never measured Android latency.
Node postprocessing timing is labeled separately if reported.
